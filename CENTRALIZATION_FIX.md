# Сайт теперь полностью централизован! 🎉

## Что было исправлено:

### ✅ 1. **Централизация API** 
**Проблема была:** Каждый ПК думал, что он главный сервер  
**Как исправлено:**
- Все запросы используют **относительные пути** (`/api/photos`, `/api/upload`)
- Браузеры других ПК теперь отправляют данные на твой основной сервер (10.25.2.131)
- Больше нет попыток найти API локально на собственном ПК

### ✅ 2. **Единая база данных (Prisma + SQLite)**
**Проблема была:** Каждый компьютер хранил фото в своем localStorage  
**Как исправлено:**
- Установлена база данных SQLite на твоем основном ПК
- Все фото теперь хранятся в **одном месте**: `/dev.db`
- Все клиенты в сети пишут в одну и ту же БД
- Если загружают фото с ПК №2, оно сохраняется в центральную БД и видно на ПК №1

### ✅ 3. **Исправление путей к изображениям**
**Как исправлено:**
- src картинок формируются как `/uploads/{filename}`
- Это относительный путь → браузер на ПК №2 запрашивает файл с сервера (твой ПК через 10.25.2.131)
- Картинки сохраняются в `/public/uploads/` на сервере

### ✅ 4. **Модерация по умолчанию (Status = pending)**
**Как исправлено:**
- При загрузке фото в БД поле `status` **автоматически** устанавливается в `'pending'`
- Администратор видит все фото в админке и может одобрить их
- Неодобренные фото НЕ появляются в публичной галерее

## Измененные файлы:

### API Routes
- **`src/app/api/upload/route.ts`** - теперь сохраняет фото + метаданные в БД
- **`src/app/api/photos/route.ts`** - возвращает фото из БД (отфильтрованные по статусу)

- **`src/components/UploadComponent.tsx`** - отправляет uploaderName + uploaderEmail в API

- **`prisma/schema.prisma`** - модель Photo для БД
- **`src/lib/prisma.ts`** - singleton для безопасного использования Prisma

## Как использовать:

### На основном сервере (твой ПК):
```bash
npm run dev
# или
npm run start
```
Сервер должен быть доступен по адресу: **http://10.25.2.131:3000**

### На других ПК в сети:
1. Откройте в браузере: `http://10.25.2.131:3000`
2. Загружайте фото - они сохранятся в центральную БД
3. На твоем основном ПК (в админке) увидите все загруженные фото
4. Одобрите фото - оно появится в публичной галерее на всех ПК

## Технические детали:

### Как работает синхронизация:
1. **Клиент на ПК №2** → отправляет фото на `/api/upload`
2. **Сервер (ПК №1)** → сохраняет файл в `/public/uploads/`
3. **Сервер** → записывает метаданные в `/dev.db`
4. **Клиент на ПК №1** → GET `/api/photos` получает из БД
5. **Клиент на ПК №2** → GET `/api/photos` получает из БД (одни и те же данные!)

### LikedBy формат:
- Хранится как: `"user-1,user-2,user-3"` (comma-separated)
- При загрузке преобразуется в массив: `["user-1", "user-2", "user-3"]`

### Status значения:
- `'pending'` - ждет одобрения (видно только в админке)
- `'approved'` - одобрено (видно в публичной галерее)
- `'rejected'` - отклонено (видно в админке в отдельной табе)
